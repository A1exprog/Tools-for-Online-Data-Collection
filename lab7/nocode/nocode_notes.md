# No-code часть (n8n)

Файлы:
- `workflow.json` — сбор 5 страниц quotes.toscrape.com (50 цитат ≥ 30) с устойчивостью;
- `error_workflow.json` — обработчик сбоев. Импортировать отдельно и выбрать его в настройках
  основного workflow: Settings → Error workflow.

```
Schedule (06:00) → Build URL List (5 страниц) → Loop Over Items (батч 1)
   → Wait 2–3 с (джиттер) → HTTP Request (Retry On Fail: 3 попытки × 5 с, таймаут 15 с)
        ├─ успех  → Parse quotes (+ детектор маркеров) → IF есть текст → Log OK / Log Warning → Loop
        └─ ошибка → Log HTTP Error → Loop
   → (цикл закончен) Итог прогона → IF «меньше 30 цитат, подозрения или ошибки»
        ├─ да  → Telegram: тревога
        └─ нет → Telegram: сводка (без звука)
Error Trigger (отдельный workflow) → Telegram: сбой workflow
```

## Механизмы устойчивости: код против no-code

| Механизм | В коде (`src/`) | В n8n | Что реализовать не удалось |
|---|---|---|---|
| Контроль скорости | token bucket по доменам, джиттер 20–30 %, адаптивный интервал по латентности | Loop Over Items (батч 1) + Wait `2 + Math.random()` с | Лимит одинаков для всех доменов; нет адаптации к латентности и к 429/503 |
| Распределённый лимит | общий счётчик в файле под блокировкой ОС (`SharedDomainLimiter`), замер на 4 процессах | — | Параллельные выполнения workflow ничего не знают друг о друге; нужен внешний Redis/БД |
| Повторы | классификация ошибок, full jitter, кэп, бюджет на URL, Retry-After, без повторов для 4xx | Retry On Fail: 3 попытки, фиксированная пауза 5 с | Повторяет любые ошибки, включая 404 и 403; Retry-After не читается; нет джиттера и бюджета |
| Предохранитель | `DomainBreaker`: closed → open → half-open, пробный запрос | — | Нет состояния между элементами и запусками. Эмуляция через static data в Code — это уже код |
| Условные запросы | ETag / Last-Modified в `state/etags.json`, 304 | — | HTTP Request не хранит валидаторы между запусками; заголовки можно подставить вручную, но хранить их негде без БД |
| Инкрементальность | водяной знак `state/watermark.json` | — | Только через внешнюю таблицу и сравнение в Code |
| Детектор блокировок | код + маркеры + размер + ожидаемые элементы, артефакты, сравнение с историей | маркеры в Code «Parse quotes», IF на пустой текст | Нет сохранения артефактов и сравнения с медианой прошлых прогонов |
| Ветка ошибки + уведомление | `incident` в журнале, код возврата 2 | error-выход HTTP Request, Error Trigger → Telegram | — |
| Проверка результата | пороги оповещений (8 шт.), статус прогона | Итог прогона → IF `< 30` | Только один порог |
| Структурные логи | JSON Lines: ts, run_id, event, host, url, status, ms, attempt, bytes, error | Log-узлы формируют JSON, но он живёт в истории выполнений | Нет p95, трафика и распределения кодов без выгрузки во внешнее хранилище |
| Расписание | внешний cron / Планировщик Windows | Schedule Trigger | — |

## Оценка стоимости

Объём: 5 страниц в день, 1 запуск workflow в день (+ запуск error-workflow только при сбое).

- Запусков в месяц: ~30 (до ~60, если каждый день будут сбои). Запросов к сайту: 5 × 30 = 150 в месяц.
- n8n Cloud считает **выполнения workflow**, а не запросы и не узлы. Тариф Starter: 2 500 выполнений
  в месяц, €20/мес при оплате за год (€240/год). Наш объём — около 1–2 % лимита.
- Pro (10 000 выполнений, €50/мес при оплате за год) понадобится, только если запускать сбор
  каждые 15 минут: 96 × 30 ≈ 2 900 выполнений в месяц.
- Self-hosted Community Edition (наш вариант, `docker run n8nio/n8n`) бесплатна. Платим только за
  сервер: для такой нагрузки хватит самого маленького VPS. Лимитов на выполнения нет.
