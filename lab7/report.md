## 1. Цель и выбранный сборщик

Цель — довести собственный сборщик до устойчивого, вежливого и наблюдаемого пайплайна и подтвердить правомерность сбора.

За основу взят сборщик цитат quotes.toscrape.com из ЛР4:
- страницы `/js/page/N/` рисуются JavaScript, поэтому открываются в браузере. Используется установленный Google Chrome 156 через Playwright (`channel="chrome"`). Если Chrome не найден, берётся Chromium из комплекта Playwright;
- карточки авторов забираются HTTP-запросами;
- httpbin.org нужен для ресурсов с ETag / Last-Modified и для кодов ответа;
- собственный стенд `src/stub_server.py` на 127.0.0.1:8765 даёт синтетические сбои. Все его ответы помечены заголовком `X-Synthetic: 1`.

Каждый сетевой запрос проходит один и тот же путь:

```
robots.txt → стоп-лист доменов (детектор) → предохранитель домена → token bucket + адаптивная задержка
→ запрос (If-None-Match / If-Modified-Since, Accept-Encoding) → классификация ответа
→ повтор / отказ / Retry-After → детектор содержимого → структурный лог → отчёт → пороги оповещений
```

## 2. Аудит исходного сборщика

| Механизм | Было | Стало |
|---|---|---|
| Ограничение скорости | token bucket без адаптации, один на процесс | token bucket по доменам + джиттер 20–30 % + адаптивный интервал + общий счётчик для нескольких процессов (`limiter.py`) |
| robots.txt | не читался | `robots.py`: can_fetch, crawl_delay, request_rate, Sitemap, разбор кода 404 |
| Повторы | backoff без бюджета, 401/403 только помечались | классификация из 11 классов, full jitter, кэп, лимит попыток, бюджет на URL, Retry-After в обоих форматах, обновление токена при 401, инцидент при 403 (`retry.py`) |
| Предохранитель | half-open пропускал любое число запросов, ни разу не срабатывал | три состояния, ровно один пробный запрос, активации в метриках (`breaker.py`) |
| Снижение нагрузки | TTL-кэш HTML, gzip выключен | ETag / Last-Modified → 304, gzip, водяной знак, блокировка картинок и шрифтов в браузере |
| Детектор | маркеры и размер, без кода ответа и артефактов | код + маркеры + размер + ожидаемый элемент; артефакты со скриншотом, остановка домена, код возврата 2, сравнение с историей (`detector.py`) |
| Логи и отчёт | события без единого набора полей; отчёт без порогов | у каждой строки поля ts, run_id, event, host, url, status, ms, attempt, bytes, error; отчёт строится из лога; 8 порогов и статус прогона (`observability.py`) |

## 3. Управление скоростью и robots.txt

**robots.txt** (`python run.py robots` → `state/robots.json`):

| Хост | Ответ | Трактовка | can_fetch | Crawl-delay / Request-rate / Sitemap |
|---|---|---|---|---|
| quotes.toscrape.com | 404 | файла нет. По RFC 9309 это «ограничений нет», работаем по своим лимитам | True для `/js/page/1/`, `/api/quotes`, `/author/…`, `/tag/…`, `/login` | не заданы |
| httpbin.org | 200 | файл найден, правила применены | True для `/etag/…`, `/cache`, `/status/503`, `/delay/3` | не заданы |

Если Crawl-delay задан, он важнее собственных настроек: `DomainLimiter.set_crawl_delay()` снижает скорость до 1/Crawl-delay при всплеске 1. Ответы 401 и 403 на запрос robots.txt, а также 5xx и недоступность трактуются как «сбор запрещён».

**Значения лимитов (`config.yaml`) и их расчёт.**

Замеры:
- медиана латентности HTTP-запроса к quotes.toscrape.com — 172–188 мс;
- p95 — около 0,9 с;
- загрузка страницы в браузере — 0,4–1,5 с;
- объём прогона — 27 запросов, из них 23 к quotes.toscrape.com.

Решения:
- **0,5 запроса/с на домен, всплеск 2.** Интервал 2 с более чем вдвое превышает p95 латентности, поэтому даже в худшем случае у сервера не бывает больше одного нашего запроса в обработке. Прогон занимает около минуты (B — 60,9 с), для ежедневного сбора это приемлемо. Всплеск 2 позволяет сразу после страницы списка запросить первого автора.
- **httpbin.org: 1 запрос/с.** Публичный тестовый сервис, а его ресурсы маленькие (около 0,3 КБ).
- **Джиттер +20–30 % к паузе**, чтобы запросы не шли ровным ритмом.
- **Адаптивный интервал = max(1/rate, 2 × EWMA латентности).** При 429 или 503 интервал удваивается, до потолка 30 с. После успешных ответов он плавно возвращается к норме (×0,75 за ответ). В сценарии S4 после серии 503 интервал к стенду вырос, и это видно по разреженным точкам на графике `codes_timeline_breaker.png`.

**Запуск в 4 параллельных процесса.** Если у каждого процесса свой ограничитель, суммарная скорость умножается на число процессов. Есть три варианта решения: один воркер на домен, общая очередь или общий счётчик. Реализован общий счётчик (`SharedDomainLimiter`): файл `state/locks/<домен>.json` хранит момент, раньше которого следующий запрос отправлять нельзя. Чтение и запись этого файла идут под блокировкой ОС (`msvcrt` в Windows, `fcntl` в Linux). Замер `python run.py parallel` (4 процесса по 10 запросов, цель 2 запроса/с):

| Вариант | Запросов | Фактическая скорость | Минимальный интервал | Длительность |
|---|---:|---:|---:|---:|
| Раздельные ограничители | 40 | **8,65 запроса/с** (×4,3 к цели) | 0,000 с | 4,5 с |
| Общий счётчик | 40 | **2,00 запроса/с** | 0,499 с | 19,5 с |

## 4. Политика повторов

| Код / исключение | Класс | Повтор | Действие |
|---|---|---|---|
| 2xx | ok | — | детектор содержимого |
| 304 | not_modified | нет | берём сохранённую копию |
| 429 | rate_limited | да | Retry-After, иначе backoff; интервал домена ×2 |
| 5xx | server_error | да | backoff, отказ считается предохранителем |
| таймаут соединения, чтения, селектора; 408 | timeout | да | backoff (браузер — 2 попытки, затем деградация) |
| обрыв, DNS, сброс соединения | connection | да | backoff |
| 401 | auth_expired | нет | один раз обновить токен и повторить, иначе остановка |
| 403 | possible_block | нет | инцидент, домен останавливается |
| прочие 4xx (400, 404, 410) | client_error | нет | ошибка запроса, повтор бессмыслен |
| маркеры капчи / блокировки при 200 | content_block | нет | инцидент со скриншотом, домен останавливается |

Параметры:
- задержка: full jitter, `U(0, min(cap, base · 2^(n−1)))`, base 1 с, cap 20 с;
- не больше 4 попыток на URL, бюджет на URL 45 с;
- Retry-After важнее собственного расчёта и понимает оба формата, секунды и HTTP-дату. Значение больше 60 с не ждём: такой URL снимается по бюджету.

Каждая попытка пишется в журнал: номер, код, задержка и её источник (`delay_source`). Журнал попыток сценария S5:

| Ресурс | Попытка 1 | Задержка (источник) | Итог |
|---|---|---|---|
| стенд `/ratelimit` | 429, `Retry-After: 2` | 2,000 с (Retry-After) | 200 |
| стенд `/ratelimit-date` | 429, `Retry-After: Mon, 02 Nov 2026 15:58:11 GMT` | 2,984 с (Retry-After, дата) | 200 |
| стенд `/ratelimit-noheader` | 429 без заголовка | 0,182 с (backoff) | 200 |
| стенд `/auth` | 401 | токен обновлён, повтор без задержки | 200 |
| httpbin `/status/500` | 500 | 0,608 → 1,250 → 2,211 с (backoff, растёт) | после 4 попыток отказ «исчерпаны попытки» |
| httpbin `/status/404` | 404 | — | без повторов: класс client_error |
| httpbin `/delay/12` | 400 | — | без повторов. httpbin.org не принимает задержку больше 10 с и отвечает 400, поэтому сетевой таймаут здесь воспроизвести не удалось. Класс timeout показан в S1 (таймаут селектора) |

## 5. Предохранитель

Предохранитель работает отдельно для каждого домена:
- **closed** — запросы идут, отказы считаются подряд;
- **open** — после 3 отказов подряд запросы к домену не отправляются 15 с;
- **half-open** — после паузы пропускается ровно один пробный запрос. Успех возвращает в closed, отказ — снова в open.

Сценарий S4: стенд отвечает 503 на первые 4 обращения. Запросы к стенду чередуются с запросами карточек авторов quotes.toscrape.com.

| Время | Событие |
|---|---|
| 15:55:23–15:55:37 | 3 ответа 503 подряд (попытки 1–3 с backoff) → **open** |
| 15:55:40–15:55:49 | 6 пропусков `breaker_skip`, остаток паузы 12,2 → 2,4 с; авторы quotes.toscrape.com собираются |
| 15:55:52 | **half-open**, пробный запрос → 503 → снова **open** |
| 15:55:54–15:56:06 | ещё 7 пропусков |
| 15:56:09 | **half-open** |
| 15:56:26 | пробный запрос → 200 → **closed**, дальше все запросы к стенду успешны |

Итог прогона:
- 2 активации предохранителя, 13 пропущенных запросов к стенду;
- 4 ответа 503 вместо возможных 20+;
- все 20 карточек авторов quotes.toscrape.com собраны (27 записей, включая 7 успешных ответов стенда).

Отказ одного домена не остановил другой. Число активаций попадает в метрику `breaker_activations` и в оповещение.

## 6. Снижение нагрузки

| Механизм | Прогоны | Запросов до | Запросов после | Трафик до, КБ | Трафик после, КБ | Экономия, % |
|---|---|---:|---:|---:|---:|---:|
| Условные запросы (ETag / Last-Modified → 304) | C_cold → C_warm | 4 | 4 | 1,2 | 0,0 | **100** |
| Сжатие (`Accept-Encoding: gzip`), карточки авторов | B → C_cold | 20 | 20 | 65,8 | 65,8 | **0** |
| Инкрементальность (водяной знак) | C_cold → C_warm | 23 | 1 | 128,3 | 56,9 | **55,6** |
| Браузер без картинок, шрифтов и медиа (дополнительно) | B → C_cold | 3 | 3 | 120,8 | 62,5 | **48,3** |

Подробности по механизмам:
- **Условные запросы.** ETag и Last-Modified сохраняются в `state/etags.json`, тело ответа — в `state/http_cache/`. На повторном прогоне все 4 ресурса httpbin.org вернули 304 без тела. Трафик посчитан по телам ответов, заголовки (около 0,2 КБ на ответ) в него не входят. quotes.toscrape.com ETag и Last-Modified не отдаёт, поэтому механизм показан на httpbin.org. Для сайта код тоже готов: заголовки отправятся, как только сервер начнёт их выдавать.
- **Gzip.** Байты «по проводу» считаются до распаковки (`raw.read(decode_content=False)`). quotes.toscrape.com на `Accept-Encoding: gzip` отвечает без `Content-Encoding`, то есть не сжимает ответы, отсюда честные 0 %. Распаковка gzip и deflate в коде поддержана.
- **Водяной знак.** `state/watermark.json` хранит идентификаторы собранных цитат и авторов. На повторном прогоне первая страница целиком состоит из известных цитат, поэтому сборщик останавливает пагинацию (`watermark_stop`: страниц 2–3 нет). Известных авторов он тоже не запрашивает. В C_warm пропущено 10 запросов, подтверждено 22 записи без загрузки.
- **Блокировка ресурсов браузера.** Сделана через CDP `Network.setBlockedURLs`, а не `page.route`. `page.route` отключает HTTP-кэш браузера, и трафик бы, наоборот, вырос.

## 7. Детектор блокировок и деградации

Вердикт строится по четырём признакам:
- код ответа: 403 — блокировка, 429 — подозрение;
- текстовые маркеры: `captcha`, `recaptcha`, `access denied`, `доступ ограничен`, `unusual traffic` и др.;
- аномально малый ответ: меньше 1500 Б;
- отсутствие ожидаемого элемента (`.quote`, `.author-details`, поле `quotes` в JSON) при коде 200.

Возможные вердикты: ok, подозрение, блокировка. При блокировке:
- сбор домена останавливается;
- в `logs/incidents/<run>_<время>/` сохраняются тело ответа, заголовки и метаданные, а при браузерном сборе ещё и скриншот;
- в журнал пишется событие `incident`;
- процесс завершается с кодом 2.

Разобранные случаи (S3 и S1):

| Ответ | Источник | Вердикт | Причины | Реакция |
|---|---|---|---|---|
| `/tag/no-such-tag-lab7/` — 200 без цитат | реальный сайт | подозрение | нет элемента `.quote` | запись отброшена, сбор продолжается |
| `/stub/empty` — «тихая заглушка» 200 | стенд | подозрение | нет элемента `.quote` | запись отброшена |
| `/stub/forbidden` — 403 «Access denied» | стенд | **блокировка** | HTTP 403, маркер access denied | инцидент, домен 127.0.0.1 остановлен |
| `/stub/captcha` в браузере — 200 | стенд | **блокировка** | маркеры captcha / recaptcha, 153 Б < 1500 Б, нет `.quote` | инцидент + `screenshot.png`, домен localhost остановлен; следующий запрос к нему — `stopped_skip` |
| `/author/Albert-Einstein/` после двух блокировок | реальный сайт | ok | — | другой домен продолжает работать |
| `/js-delayed/page/1/` — селектор не дождались | реальный сайт | подозрение | `wait_for_selector: Timeout 3000ms` | артефакт со скриншотом, деградация до HTTP (S1) |

**Сравнение с историей.** Объём записей и средний размер ответа сравниваются с медианой прошлых прогонов того же профиля (`reports/history.jsonl`). Отклонение больше 20 % даёт жёлтый статус, больше 30 % — красный. Механизм уже сработал на деле. Первые прогоны шли без браузера: Chromium не был установлен, сбор ушёл на HTTP-эндпоинт, и средний ответ был втрое меньше. В следующем прогоне, уже с браузером, сравнение дало «красный», то есть подмену режима сбора оно поймало. Эти 6 записей признаны некорректной базой и перенесены в `reports/history_invalid_no_browser.jsonl`.

## 9. Наблюдаемость

**Структурные логи.** Одна строка — один JSON-объект с обязательными полями `ts` (UTC, ISO 8601), `run_id`, `event`, `host`, `url`, `status`, `ms`, `attempt`, `bytes`, `error`, а также служебными полями `error_class`, `via`, `wait_s`, `delay_source` и др. Пример:

```json
{"ts": "2026-11-02T15:58:08.015+00:00", "run_id": "S5_retry_policy", "event": "retry", "host": "127.0.0.1:8765",
 "url": "http://127.0.0.1:8765/ratelimit-date", "status": null, "ms": null, "attempt": 2, "bytes": null, "error": null,
 "delay_s": 2.984, "delay_source": "Retry-After", "error_class": "rate_limited", "retry_after": "Mon, 02 Nov 2026 15:58:11 GMT"}
```

**Отчёт о прогоне** (`reports/run_report_<id>.json`) пересчитывается из журнала. В нём:
- число запросов, распределение кодов, доля ошибок, доля 429 и 403, число повторов;
- медиана и p95 латентности, трафик, число ответов 304;
- активации предохранителя, собранные и отброшенные записи, длительность.

**Пороги оповещений** — `evaluate_alerts()` возвращает список сработавших оповещений и статус прогона:

| Метрика | Порог | Уровень | Обоснование |
|---|---|---|---|
| error_rate | > 10 % | red | источник деградирует или мы его перегружаем |
| share_429 | > 2 % | yellow | приближаемся к лимиту сайта |
| share_403 | > 0 | red | любой 403 — возможная блокировка |
| latency_p95_ms | > 3000 мс | yellow | при норме около 0,9 с это перегрузка сервера |
| breaker_activations | > 0 | yellow | один из доменов был недоступен |
| collected + known | < минимума прогона (30; 10 для инкрементального) | red | тихая заглушка или поломка селекторов |
| block_verdicts | > 0 | red | детектор вынес вердикт «блокировка» |
| history | отклонение > 20 / 30 % от медианы | yellow / red | деградация объёма или размера ответа |

## 11. No-code (n8n)

Workflow `nocode/workflow.json` собирает 5 страниц quotes.toscrape.com, то есть 50 цитат:
- контроль скорости — Loop Over Items с батчем 1 и Wait `2 + Math.random()` с;
- повторы — Retry On Fail, 3 попытки по 5 с;
- ошибки — error-выход HTTP-узла;
- детектор маркеров в узле Code;
- проверка итога: меньше 30 цитат, подозрения или ошибки → Telegram «тревога», иначе тихая сводка;
- расписание — каждый день в 06:00;
- обработчик сбоев — отдельный workflow `nocode/error_workflow.json` с Error Trigger и отправкой в Telegram.

| Механизм | Код | n8n | Что не удалось |
|---|---|---|---|
| Контроль скорости | token bucket по доменам, джиттер, адаптивный интервал | Wait со случайной паузой 2–3 с, батч 1 | один лимит на всё, нет адаптации к латентности и к 429 |
| Распределённый лимит | общий счётчик под блокировкой ОС, замер 2,00 запроса/с на 4 процессах | — | параллельные запуски workflow не знают друг о друге; нужен внешний Redis или БД |
| Повторы | классы ошибок, full jitter, кэп, бюджет, Retry-After, 4xx без повторов | Retry On Fail: 3 × 5 с | повторяет и 404, и 403; не читает Retry-After; пауза без джиттера |
| Предохранитель | closed → open → half-open по доменам | — | нет состояния между элементами и запусками без кода и внешнего хранилища |
| Условные запросы | ETag / Last-Modified → 304 | — | валидаторы негде хранить между запусками |
| Детектор | код, маркеры, размер, элемент, артефакты, история | маркеры в Code + IF | нет артефактов и сравнения с медианой прошлых прогонов |
| Ветка ошибки и уведомление | incident, код возврата 2 | error-выход, Error Trigger, Telegram | — |
| Расписание | внешний cron / Планировщик Windows | Schedule Trigger | — |

**Стоимость.** n8n Cloud считает запуски workflow, а не запросы. Ежедневный сбор — около 30 запусков в месяц (до 60, если каждый день будут сбои). Тарифа Starter (2 500 запусков, €20/мес при оплате за год) хватает с запасом в 40 раз. Pro (10 000 запусков, €50/мес) понадобился бы только при запуске каждые 15 минут. Self-hosted Community Edition бесплатна, расходы — только на сервер. Подробнее в `nocode/nocode_notes.md`.

## 12. Правовой чек-лист

Полностью — `legal_checklist.md`. Кратко:
- **Источники:** учебная площадка quotes.toscrape.com, тестовый сервис httpbin.org и собственный стенд.
- **Запрета на автоматический сбор нет.** robots.txt проверен кодом: у quotes.toscrape.com его нет (404), у httpbin.org все нужные пути разрешены.
- **Авторизация не используется.** Средства обхода защиты не применяются: капча не решается, а останавливает сбор домена; отпечатки и User-Agent не подменяются.
- **Нагрузка:** не больше 0,5 запроса/с на домен, около 27 запросов за прогон.
- **Состав данных:** цитаты и открытые сведения об известных авторах. Целенаправленной обработки персональных данных нет.
- **Хранение:** локально, до защиты работы, потом удаляется.
- **User-Agent** `EducationalCrawler/1.0 (+https://example.edu; contact: student@example.edu)`.
- **При претензии или блокировке** сбор останавливается, данные удаляются.

## 13. Выводы

1. Пайплайн воспроизводит все три сценария варианта 4. Таймаут селектора и недоступный браузер приводят к деградации до JSON-эндпоинта без потери данных. Заглушка и капча распознаются по содержимому, а не только по коду ответа.
2. Повторы классифицированы: 4xx не повторяются, Retry-After в обоих форматах важнее собственного расчёта, 401 обрабатывается обновлением токена, 403 — остановкой домена.
3. Предохранитель изолирует отказ: 13 запросов к недоступному домену не отправлены, а соседний домен собран полностью.
4. Из трёх обязательных механизмов снижения нагрузки сработали два: условные запросы (−100 % трафика на ресурсах с валидаторами) и водяной знак (−56 %). Сжатие дало 0 %: сайт не отдаёт gzip. Блокировка картинок и шрифтов в браузере добавила −48 %.
5. Общий лимит для 4 процессов держит заявленные 2 запроса/с. Раздельные лимиты превышают их в 4,3 раза.
6. Слой надёжности плохо переносится в n8n: предохранитель, условные запросы и распределённый лимит без кода и внешнего хранилища не реализуются.
